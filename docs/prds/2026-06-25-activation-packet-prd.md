# OKFY Activation Packet PRD

Date: 2026-06-25
Status: Approved for implementation by active goal continuation

## Problem

OKFY can already crawl or import docs, validate OKF bundles, preview them with Inspector, and serve them through a local MCP server. The remaining adoption gap is the first useful moment: a developer still has to trust the tool, copy setup snippets, open a separate Inspector file, and imagine whether an agent will actually search, read, and cite the docs correctly.

The market around agent-ready docs is moving toward lower-friction setup and shareable proof. Context7 emphasizes fresh, version-specific docs over MCP. Ref sells agentic docs search for public and private docs. Mintlify now exposes `llms.txt`, hosted MCP, and contextual "open in agent" actions. The `llms.txt` proposal and related issue threads show that developers want machine-readable docs, but also complain when giant exports are too large, stale, or hard to verify.

OKFY should not chase a hosted registry first. Its sharper wedge is local-first proof: "Here is exactly what your agent can see from this docs source, here is the MCP config, and here is a small proof transcript with citations."

## Goal

Add an activation packet flow that turns any supported OKFY target into a small local folder containing:

- A static Inspector HTML file.
- A setup Markdown file with exact MCP command/config and first prompt for the selected client.
- A proof JSON file showing the agent-facing tool-call path over the selected docs.

This makes OKFY easier to try, easier to send to a teammate, and easier to trust before wiring it into Claude, Codex, Cursor, or a generic MCP client.

## Users

- Developers evaluating OKFY on a third-party docs source.
- Maintainers who want to show "our docs are agent-ready" without adopting a hosted docs platform.
- Teams with private/internal docs that need a local-first MCP and citation path.

## Requirements

1. `okfy activate [targets...]` accepts the same target styles as `okfy map`: registered source names, local OKF bundle paths, multi-source workspaces, and `--all`.
2. The command writes a packet directory, defaulting to `okfy-activation/`.
3. The packet includes `okfy-inspector.html`, `okfy-setup.md`, and `okfy-proof.json`.
4. The setup document includes the selected client, MCP launch command, client artifacts, first prompt, readiness status, and generated file list.
5. The proof JSON includes a deterministic `bundle_summary`-style summary plus a concrete `search_concepts`, `read_concept`, and, when available, `get_neighbors` example derived from the bundle.
6. The Inspector HTML generated by activation includes the setup command and first prompt as copyable text.
7. The command refuses to overwrite a non-empty packet directory unless `--force` is passed.
8. The command supports `--client claude-code|claude-desktop|cursor|codex|generic`.
9. The command supports `--json`, printing the packet manifest without human prose.
10. Activation must not write MCP client config files by default.

## Non-Goals

- Hosted OKFY sharing.
- A cloud registry.
- Embedding search.
- Mutating Claude, Codex, Cursor, or desktop config files.
- Full `llms.txt` export. That remains a good follow-up, but the activation packet should prove setup and citation readiness first.

## Success Criteria

- A user can run `npx -y okfy-ai activate examples/bundles/stripe-checkout-small --client codex --out ./okfy-activation` and immediately inspect the generated setup, HTML, and proof files.
- The proof packet demonstrates the same agent path OKFY recommends: summarize, search, read, and inspect neighbors.
- Existing `map`, `serve`, `init`, and `doctor` behavior remains compatible.
- Public docs lead with activation as the fastest way to see the OKFY value loop.

## Evidence

- Context7 shows strong demand for fresh docs over MCP: https://github.com/upstash/context7
- Ref positions token-efficient docs search as agent infrastructure: https://docs.ref.tools/
- Mintlify exposes agent-ready docs surfaces including `llms.txt` and MCP: https://www.mintlify.com/docs/ai/llmstxt
- `llms.txt` frames the machine-readable docs problem: https://llmstxt.org/
